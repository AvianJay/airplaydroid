# FairPlay: implementation status

**Status: the FairPlay SAP response core is COMPLETE and ACCEPTED BY REAL HARDWARE.**

## The chain

```
m2 challenge (128 B)
  └─ Phase 1: FairPlayWhiteBox.phase1(challenge)                  ✅  gp buffer
       └─ Bridge: FairPlaySapCore.bridgeX9HeadForSap(localSap, gp) ✅  x9Data (20 B)
            └─ Phase 2: FairPlayPhase2.exchangeFromX9(x9Data)      ✅  response (20 B)
                 └─ FairPlayRecords.m3(mode, localSap, response)   ✅  encrypted body
```

`FairPlayPhase2` is ported from upstream's Go `fairplayhash/` package (25 files,
~92 KB). The port lives in three files:

| File | Size | Role |
|---|---|---|
| `FairPlayPhase2Tables.kt` | 54 KB | every constant table, unpacked at init |
| `FairPlayPhase2Rounds.kt` | 24 KB | NEON prologue, WB-MD5 rounds, staging |
| `FairPlayPhase2Spn.kt` | 20 KB | the two white-box AES SPN passes |
| `FairPlayPhase2.kt` | 7 KB | the analytical pipeline driver |

Tables are generated by `_research/gen_phase2_tables.py`, which decodes the Go
string-escape table literals — hand-transcribing those corrupts them silently.

## Two real bugs, both found by hardware, neither by the test suite

### 1. Phase 2 was entirely missing

The bridge output is an *input* to Phase 2, not the answer. Returning it directly
produced 20 well-formed bytes that every receiver rejected — and a rejected m3 is
indistinguishable from an unevaluated one, so nothing looked wrong.

Why the suite missed it: it checked two **components** (70/70 vectors) rather than
the whole chain. The full-chain corpus would have caught it, and now does.

### 2. The m3 body was not encrypted

`FairPlayRecords.m3` wrote the local SAP **in the clear**. Upstream:

```go
body := fpsapcore.EncryptMessageBodyMode3(s.localSAP)
copy(m3[16:144], body[:])
```

`FairPlayMessageCipher.encryptBody` existed, was unit-tested, and was **never
called on this path**. The frame had correct framing, a correct label and a
correct response — and every receiver rejected it, because the body it decrypted
was not the SAP the response was computed over.

This is the bug that actually blocked hardware acceptance. Fixing it turned
5/5 rejections into 5/5 acceptances.

## Why a component test cannot catch these

Both bugs produce output that is the right *shape*: 20 bytes, or a 164-byte frame
with correct framing. Only an oracle that spans the whole chain — a full-chain
vector, or a receiver — can see them. The lesson is recorded because it cost two
rounds: **"N/N vectors pass" is a statement about what those vectors cover, and
nothing more.**
